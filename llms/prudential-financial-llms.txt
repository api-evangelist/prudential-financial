SIFE products do not use max face amount validation.</p>

- [Policy Package Signature](/document-management-api/policy-package-signature.md) - Policy Package Signature. <p>Performs actions required to sign Policy Package documents</p> <p>There are several different behaviors of this operation, depending upon the current state of signing and whether optional URL parameters have been supplied...</p> <ol> <li>If Policy Package signing has yet to be started... <ul> <li>If payment has not yet been received, an error will be returned due to a conflict between lack of payment and the attempted signature operation</li> <li>If payment has been received, signing will be initialized with a signing initiation email sent to the first signer</li> </ul> </li> <li>If Policy Package signing has been started - and no optional URL parameters have been supplied - real-time synchronization with the signing vendor will be performed <ul> <li>While inbound signing status events are expected from the signing vendor within a minute or two of any signing action, they may be delayed or, potentially, fail to be received</li> <li>This synchronization feature will perform real-time polling of the signing vendor for status, providing the very latest signing status without having to wait for any inbound signing status event</li> <li>This is as opposed to the Policy Package Status operation, which is a lighter-weight operation that will provide the list of documents and report the latest known signing status without any attempted synchronization</li> </ul> </li> <li>If Policy Package signing has been started, and the optional <code>resend</code> URL parameter is supplied, a signing initiation email is re-sent to the current signer <ul> <li>Note: A signer may enter their access code incorrectly too many times resulting in being locked out of signing, in which case re-sending the email will also serve to unlock signing; re-enabling the signing link in both new and prior signing initiation emails</li> </ul> </li> <li>If Policy Package signing was systematically voided or declined by an individual signer, and the optional <code>reset</code> URL parameter is supplied, signing will be re-initialized with a signing initiation email sent to the first signer</li> <li>If Policy Package signing was successfully completed but authorized documents not yet submitted, the request is a NOP with a reminder that the documents are authorized and ready to be submitted</li> <li>If Policy Package signing was successfully completed and authorized documents already submitted, the request is a NOP with a message that the documents are both authorized and submitted</li> </ol>
